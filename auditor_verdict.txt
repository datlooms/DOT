PART 7 — CARRIED FORWARD

A. The plateau reasoning does NOT survive the design change. Refuted.

The argument: 30.0/31.4 was measured on random VALID-passing triples; real candidates additionally cleared PF≥2, so they are a strict subset; therefore the true figure lands at or below the plateau. The monotonicity step is sound — coverage is non-decreasing in the signal set, so a subset of signals covers no more episodes.

But the premise no longer holds. Under this rebuild the catalogue is emitted from VALID with no PF bar — the checklist is explicit: "No PF bar, no WR bar; those are columns." The catalogue is therefore not the PF≥2 subset; it is the full VALID set, which is precisely the population the plateau was measured on. The expected result is at the plateau, not below it. The strict-subset argument describes the old S5-filtered funnel that this rebuild removes.

This matters operationally: DEVELOPER_BRIEF's REPORT BACK says to flag immediately if the run lands "materially above or below" 30.0/31.4. Under the corrected reasoning, below is now the surprising direction — it would mean VALID is rejecting signals the proxy admitted — and at is the expected outcome rather than a ceiling touched. The asymmetry the item asserts should be restated.

B. The item-20 override is sound and the determinism carve-out is coherent — with one boundary to fix.

Profiling genuinely requires a real run at real scale; taking item 20 literally costs the operator a second full night for a table that instrumentation yields as a by-product. Speculative parallelism remains forbidden, so the item's protective intent survives. The carve-out works because timings go to the run log and the log is declared not-an-artifact while every CSV is.

The boundary is under-specified in exactly one place — book_scored.jsonl — as set out in Task 8 item 6. State the rule at file level (CSV artifacts are byte-identical and wall-clock-free; the run log and the attestation jsonl are exempt) and the carve-out is airtight.
